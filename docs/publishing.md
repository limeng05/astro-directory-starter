# Repository publishing checklist

- Publish the implementation, lockfile, license, and documentation together.
- Run `npm test` and inspect the site in a browser before publishing.
- In GitHub repository settings, enable “Template repository” if you want a “Use this template” button.
- Suggested description: “A practical Astro tool-directory starter with static pagination, searchable metadata, SEO pages, and Cloudflare Pages deployment.”
- Suggested topics: `astro`, `directory`, `starter-template`, `static-site`, `seo`, `cloudflare-pages`.
- Set About → Website to the deployed demo. If there is no demo yet, the author's primary project is a relevant alternative: `https://navsprout.com/`.
- Keep the two project references in the README descriptive and disclose ownership.
- Optionally add the snippet below to your own profile README. It is not automatically added by this repository.

```markdown
I'm building web directories and sharing practical implementation examples:

- [NavSprout](https://navsprout.com/) — curated websites, web apps, and online tools.
- [AINavly](https://ainavly.com/) — AI tools, creative applications, web projects, and browser games.
- [Astro Directory Starter](https://github.com/limeng05/astro-directory-starter) — an open-source implementation example.
```

After publication, verify that links resolve and inspect GitHub's rendered anchor attributes. Check Ahrefs Referring Domains after its crawler discovers the page. Treat discovery and DR changes as observations, not guaranteed outcomes.
